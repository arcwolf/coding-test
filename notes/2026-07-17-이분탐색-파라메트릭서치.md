# 오늘의 주제: 이분탐색 & 파라메트릭 서치 (Binary Search / Parametric Search)

> 언어: **Python**
> 정렬된 배열에서 값 찾기부터, "정답을 이분탐색"하는 파라메트릭 서치까지. 코테에서 가장 자주 나오는 기본기 중 하나.

---

## 1. 핵심 아이디어

이분탐색은 **탐색 공간을 절반씩 버리는** 알고리즘이다. 매 단계에서 "정답이 왼쪽인가 오른쪽인가"를 O(1)로 판정할 수 있으면, N개의 후보를 O(log N)에 좁힌다.

성립하는 **단 하나의 조건**: 탐색 공간에 **단조성(monotonicity)** 이 있어야 한다.
- 값 탐색: 배열이 **정렬**되어 있다 → `arr[mid] < target`이면 왼쪽 절반은 전부 target보다 작다.
- 파라메트릭 서치: 판정함수 `f(x)`가 어떤 경계 T를 기준으로 **F F F ... F T T T ...** 처럼 한 번만 바뀐다.

> **왜 동작하는가:** 단조성이 있으면 `mid` 한 지점의 판정 결과가 그 방향 전체의 답을 확정한다. 그래서 절반을 "안심하고" 버릴 수 있다. 단조성이 없으면 이분탐색은 틀린 답을 낸다 — 이게 유일하고 가장 중요한 전제.

## 2. 경계 처리 — 여기서 다 틀린다

이분탐색 버그의 90%는 **경계(off-by-one)** 와 **무한루프**다. 습관을 하나로 고정하는 게 최선. 나는 `while lo <= hi` (닫힌 구간)을 표준으로 쓴다.

### 정당성 체크 3종
1. **`mid` 계산:** `mid = (lo + hi) // 2`. Python은 큰 수 오버플로가 없지만, 습관적으로 `lo + (hi - lo) // 2`도 안전.
2. **구간이 반드시 줄어드는가:** `lo = mid + 1` 또는 `hi = mid - 1`처럼 **mid를 포함하지 않고** 갱신해야 무한루프가 안 난다. `lo = mid` 같은 건 짝수 구간에서 멈춘다.
3. **종료 시 lo/hi의 의미:** `lo <= hi` 루프가 끝나면 항상 `lo == hi + 1`. 보통 **`lo`가 "T가 시작되는 첫 위치"**, **`hi`가 "F인 마지막 위치"** 가 된다. 이 불변식을 외워두면 답을 lo/hi 중 뭘로 낼지 안 헷갈린다.

## 3. 대표 예제 1 — 파라메트릭 서치 (백준 2805 나무 자르기)

절단기 높이 H를 정하면 얻는 나무 총량이 정해진다. "총량 ≥ M을 만족하는 **가장 높은** H"를 구한다.

- 판정 `is_valid(H)`: 높이 H로 잘랐을 때 얻는 나무 합 ≥ M ?
- H가 낮을수록 많이 얻으므로, `is_valid`는 H 기준 **T T T ... F F F** (내림차순 단조). 우리가 원하는 건 **T의 마지막 위치**.

```python
import sys
input = sys.stdin.readline

def solve():
    N, M = map(int, input().split())
    trees = list(map(int, input().split()))

    def cut(h):                       # 높이 h로 잘랐을 때 얻는 나무 총량
        return sum(t - h for t in trees if t > h)

    lo, hi = 0, max(trees)
    ans = 0
    while lo <= hi:
        mid = (lo + hi) // 2
        if cut(mid) >= M:             # 충분히 얻음 → 더 높여본다
            ans = mid                 # 후보 저장
            lo = mid + 1
        else:                         # 부족 → 낮춰야 함
            hi = mid - 1
    print(ans)

solve()
```

- **핵심 아이디어:** 답(높이)을 직접 이분탐색. 최댓값을 찾으므로 성공 시 `lo`를 올리고 답을 갱신.
- **시간복잡도:** O(N log(maxH)). 판정 한 번이 O(N), 높이 범위가 최대 10^9이라 log는 약 30.
- **자주 하는 실수:** `cut`에서 `t - h`를 int로 안 하면 되지만, `sum` 안에서 음수를 안 거르면 틀림 → `if t > h` 필수.

## 4. 대표 예제 2 — 정렬 배열에서 값/개수 찾기 (bisect)

정렬된 배열에서 "값 x가 있는가", "x 이상인 첫 위치", "x의 개수"는 전부 이분탐색. Python은 `bisect`로 직접 짤 필요가 없다.

```python
from bisect import bisect_left, bisect_right

arr = [1, 2, 2, 2, 5, 7]

# x가 들어갈 가장 왼쪽 위치 (== x 이상인 첫 인덱스)
bisect_left(arr, 2)   # -> 1
# x가 들어갈 가장 오른쪽 위치 (== x 초과인 첫 인덱스)
bisect_right(arr, 2)  # -> 4

# 존재 여부
i = bisect_left(arr, 2)
found = i < len(arr) and arr[i] == 2      # True

# x의 개수 = 오른쪽 경계 - 왼쪽 경계
count = bisect_right(arr, 2) - bisect_left(arr, 2)   # 3
```

> `bisect_left`는 `arr[mid] < x`일 때 `lo = mid+1`, 아니면 `hi = mid`(반열린 구간)로 도는 내부 구현이다. 즉 "**x 이상이 처음 나오는 위치**"를 반환. `lower_bound`와 동일. 이걸 이해하면 직접 짤 때도 안 헷갈린다.

## 5. 실수 이분탐색 (부동소수점)

방정식의 근, 최적 비율 등 **연속 값**을 찾을 땐 `lo <= hi`가 아니라 **반복 횟수** 또는 **오차(epsilon)** 로 종료한다.

```python
lo, hi = 0.0, 1e9
for _ in range(100):          # 100번이면 오차 ~ 범위/2^100, 충분
    mid = (lo + hi) / 2
    if f(mid):
        lo = mid
    else:
        hi = mid
print(lo)
```

- **팁:** `while hi - lo > 1e-9`도 되지만, 절대 안 끝나는 케이스(정밀도 한계)가 있어 **고정 반복(50~100회)** 이 더 안전.

## 6. Python 템플릿 (통합)

```python
# [정수 파라메트릭] "조건을 만족하는 최댓값" 찾기
def parametric_max(lo, hi, ok):
    ans = lo - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if ok(mid):
            ans = mid
            lo = mid + 1     # 최솟값 찾으려면: hi = mid - 1 로 바꾸고 else와 교환
        else:
            hi = mid - 1
    return ans

# [lower_bound 직접 구현] x 이상인 첫 인덱스
def lower_bound(arr, x):
    lo, hi = 0, len(arr)     # 반열린 구간 [lo, hi)
    while lo < hi:
        mid = (lo + hi) // 2
        if arr[mid] < x:
            lo = mid + 1
        else:
            hi = mid
    return lo
```

## 7. 한눈 요약

- **전제는 단조성 하나.** 정렬 배열이거나 판정함수가 F→T로 한 번만 바뀌면 쓴다.
- **"정답을 직접 이분탐색"** 하는 게 파라메트릭 서치. 최소 시간/최대 크기/최적 비율 문제에 강력.
- 경계는 **`lo <= hi` + `mid±1` 갱신**으로 습관 고정 → 무한루프·off-by-one 방지.
- 값 탐색은 그냥 **`bisect`** 써라. 개수는 `bisect_right - bisect_left`.
- 실수는 **고정 반복 100회**.

시간복잡도: 판정 O(f) × O(log(범위)). 대부분 log는 30~60 안쪽이라 사실상 판정함수 비용이 전부.
